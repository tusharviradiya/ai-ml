Class Marks Report Generator

A visual guide to List Comprehensions, Functions, Lambda, *args/**kwargs, Decorators and Generators

1. The Problem

A teacher has marks for every student in a class. She wants a small program that:

  • Finds the students who passed (marks 40 and above) in one quick line. List Comprehension
  • Ranks students from highest to lowest marks. Lambda
  • Calculates an average for any number of subjects. *args
  • Creates a report with optional details such as city or club. **kwargs
  • Logs every report it builds, without changing the report code itself. Decorator
  • Reads students one at a time to save memory for a large class. Generator

Professional code uses all of these. Each one solves a real problem you will meet.

2. The Six Tools

List Comprehensions

Idea: Build a new list from another list in one line.

Real life: "Give me only the passing marks."

passed = [m for m in marks if m >= 40]

Functions

Idea: Name a block of work once and reuse it.

Real life: a recipe you can follow again and again.

def grade(marks):
    if marks >= 75:
        return "A"
    return "B"

Lambda Functions

Idea: A tiny, nameless function for a quick job.

Real life: a one-line instruction written on the spot.

ranked = sorted(students, key=lambda s: s["marks"], reverse=True)

*args and **kwargs

Idea: Accept a flexible number of inputs.

*args = extra positional values (a tuple). **kwargs = extra named values (a dict).

def report(name, *marks, **info):
    ...
report("Riya", 50, 70, city="Pune")

Decorators

Idea: Wrap a function with extra behaviour, like a gift wrap.

Real life: a security guard checks people before and after they enter.

@log_call
def make_report(...):
    ...

Generators

Idea: Produce values one at a time, when asked, using yield.

Real life: a ticket counter that serves one person at a time.

def read_students(rows):
    for row in rows:
        yield row

6. Try It: *args and **kwargs

Add or remove subject marks. Watch how Python packs them into a tuple.

def average(*marks):          # marks is a tuple
    return sum(marks) / len(marks)

average(50, 70, 90)           # marks = (50, 70, 90)

Now the optional details. **info collects named values into a dictionary.

def make_report(name, *marks, **info):   # info is a dict
    ...

make_report("Riya", 50, 70, city="Pune")

7. Try It: Decorator Wrapping a Function

The decorator adds a log before and after make_report. The function itself never changes.

def log_call(func):
    def wrapper(*args, **kwargs):
        print("→ calling", func.__name__)
        result = func(*args, **kwargs)
        print("← finished", func.__name__)
        return result
    return wrapper

@log_call
def make_report(name, *marks, **info):
    ...
Log is empty.

8. Try It: Generator Yielding One Student at a Time

Click Next. Each click runs the generator only until the next yield.

def read_students(rows):
    for row in rows:
        yield row          # pause here, hand back one student

9. Your Task

  1. Create a list of at least five student dictionaries with name and marks.
  2. Write a generator read_students(rows) that yields one student at a time.
  3. Write average(*marks) that returns the average of any number of marks.
  4. Write make_report(name, *marks, **info) that returns a formatted text report. info can hold optional details like city.
  5. Add a decorator @log_call to make_report that prints a message before and after it runs.
  6. Use a list comprehension to build a list of passing students (average 40 or above).
  7. Use sorted() with a lambda to rank students by average, highest first.
  8. Print the ranked report for all students.

10. Acceptance Criteria (Tick As You Go)

The decorator prints a log line before and after make_report, and make_report itself has no logging code.
The passing list is built with a single list comprehension and includes only averages of 40 or more.
The ranking uses sorted() with a lambda key and shows the highest mark first.
The program runs without errors for at least two different classes of students.
You can explain in your own words why a generator is useful for a very large class.
