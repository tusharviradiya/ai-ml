Website Health Checker

A visual guide to Asyncio, Threading and Multiprocessing

1. The Problem

A team looks after 20 websites. Every hour, the program must:

  • Ping 20 websites and report which are up. Most of the time is spent waiting for replies. Asyncio
  • Download 10 screenshots from a server. Also mostly waiting for the network. Threading
  • Resize and compress 8 large images. This is heavy calculation that keeps the processor busy. Multiprocessing

The key question is: is my program waiting, or is it working? The answer decides which tool to use.

2. The Three Tools

Asyncio

Idea: One program switches between many tasks at each await. While one task waits for the network, the others keep going.

Real life: a waiter who takes orders from many tables and checks the kitchen between tables, rather than waiting at one table.

import asyncio

async def check(url):
    await asyncio.sleep(1)     # pretend network wait
    return f"{url} is up"

async def main():
    urls = ["a.com", "b.com", "c.com"]
    results = await asyncio.gather(*(check(u) for u in urls))
    print(results)

asyncio.run(main())

Threading

Idea: Several workers run inside the same program at the same time. Good when each worker is mostly waiting.

Real life: several cashiers in one shop, each serving a different customer.

import threading

def download(url):
    print("downloading", url)

threads = [threading.Thread(target=download, args=(u,))
           for u in ["img1.png", "img2.png"]]
for t in threads: t.start()     # start all workers
for t in threads: t.join()      # wait for all to finish

Multiprocessing

Idea: Separate programs run on separate processor cores. Best for heavy calculation.

Real life: several chefs in separate kitchens, each cooking a big meal at the same time.

from multiprocessing import Pool

def compress(image):
    ...                       # heavy CPU work

if __name__ == "__main__":
    with Pool(4) as pool:     # 4 processes
        pool.map(compress, images)

6. The Core Code (Read It Slowly)

import asyncio, threading
from multiprocessing import Pool

# ----- 1. ASYNCIO: many network checks, one program -----
async def check_site(url):
    await asyncio.sleep(1)                  # wait for the reply
    return url, "UP"

async def check_all(urls):
    return await asyncio.gather(*(check_site(u) for u in urls))

# ----- 2. THREADING: many downloads, workers wait for files -----
def download(name, results):
    # pretend to download a file
    results.append(name)

def download_all(names):
    results = []
    threads = [threading.Thread(target=download, args=(n, results)) for n in names]
    for t in threads: t.start()
    for t in threads: t.join()
    return results

# ----- 3. MULTIPROCESSING: heavy work on several cores -----
def resize(image):
    return sum(i * i for i in range(10_000_000))   # heavy CPU work

if __name__ == "__main__":
    print(asyncio.run(check_all(["a.com", "b.com", "c.com"])))
    print(download_all(["img1.png", "img2.png"]))
    with Pool(4) as pool:
        pool.map(resize, ["p1", "p2", "p3", "p4"])

Rule of thumb: asyncio and threading help when a program waits. multiprocessing helps when a program calculates. The if __name__ == "__main__" line is needed for multiprocessing.

8. Acceptance Criteria (Tick As You Go)

Each site check returns both its URL and its status, and all results are collected.
The 10 threaded downloads all start before any is joined, and all finish.
The heavy resize() work runs with multiprocessing.Pool inside an if __name__ == "__main__": block.
Timings are recorded for sequential and concurrent runs, and the program prints both.
Each part has a comment that says "waiting" or "calculating" and explains the tool chosen.
The program runs without errors and produces the same results on two separate runs.
You can explain in your own words why asyncio is not the right choice for heavy calculation.
