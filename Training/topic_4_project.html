Mini Bank Account System

A visual guide to Classes and Objects, Inheritance, Polymorphism and Encapsulation

1. The Problem

A small bank offers three kinds of accounts. Each one holds money and behaves a little differently:

  • Basic account: deposits and withdrawals only.
  • Savings account: a basic account that also earns interest every month.
  • Current account: a basic account that pays a monthly fee.

Your program must keep each account's balance safe, reuse the common rules, and run the month-end process for every account with one simple loop.

Real banking software is built exactly this way. These four ideas are the foundation of it.

2. The Four Ideas

Classes and Objects

Idea: A class is the blueprint. An object is one thing built from it.

Real life: a cookie cutter (class) and each cookie (object).

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

riya = BankAccount("Riya", 10000)

Inheritance

Idea: A child class gets everything from its parent, and can add or change things.

Real life: a child inherits features from a parent, then adds its own.

class SavingsAccount(BankAccount):
    def __init__(self, owner, balance=0, rate=0.04):
        super().__init__(owner, balance)
        self.rate = rate

Polymorphism

Idea: The same method name behaves differently for each type of object.

Real life: "Pay" means something different for cash, card and UPI.

for acc in accounts:
    acc.month_end()   # each type does its own thing

Encapsulation

Idea: Keep the data private and change it only through safe methods.

Real life: you use an ATM buttons, not the bank vault door.

self.__balance = balance      # private
def deposit(self, amount):
    if amount <= 0:
        raise ValueError("Amount must be positive")
    self.__balance += amount

7. The Core Code (Read It Slowly)

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance              # encapsulation: private

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Amount must be positive")
        self.__balance += amount

    def withdraw(self, amount):
        if amount <= 0 or amount > self.__balance:
            raise ValueError("Invalid withdrawal")
        self.__balance -= amount

    def get_balance(self):
        return self.__balance

    def _change(self, amount):                # protected: for child classes
        self.__balance += amount

    def month_end(self):
        pass                                  # basic account: nothing happens


class SavingsAccount(BankAccount):            # inheritance
    def __init__(self, owner, balance=0, rate=0.04):
        super().__init__(owner, balance)
        self.rate = rate

    def month_end(self):                      # polymorphism: own version
        self._change(self.get_balance() * self.rate / 12)


class CurrentAccount(BankAccount):
    def month_end(self):                      # polymorphism: own version
        self._change(-50)                     # monthly fee

Notice: the child classes never touch __balance directly. They use the parent's safe methods.

8. Your Task

  1. Create a BankAccount class with owner and a private balance.
  2. Add deposit() and withdraw() methods that reject invalid amounts.
  3. Create SavingsAccount that inherits from BankAccount and adds interest in month_end().
  4. Create CurrentAccount that inherits from BankAccount and charges a fee in month_end().
  5. Make a list with at least three accounts of different types and loop through it, calling month_end() on each.
  6. Print each account's owner, type and balance after month end.
