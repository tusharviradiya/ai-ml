Daily Expense Logger

A visual guide to File Read and Write, and Exception Handling during I/O

1. The Problem

You want a small program that keeps a record of your daily spending, even after the program closes. It must:

  • Save each expense to a text file, adding it to the end without losing old ones. Write / Append
  • Read the file back and total the money spent. Read
  • Survive real problems: the file may not exist yet, a line may be damaged, or the file may be locked. Exception handling

Almost every real program saves data to files. Files fail for many reasons, so good code expects that.

2. The Three Ideas

Reading and Writing Files

Idea: open() connects your program to a file. The mode decides what you may do.

ModeMeaning
"r"Read only (file must exist)
"w"Write, erases old content
"a"Append, adds to the end

Exception Handling

Idea: try runs risky code. except catches a named error and responds calmly instead of crashing.

Real life: a bank teller who has a plan when the card reader fails.

try:
    with open("expenses.txt", "r") as f:
        data = f.read()
except FileNotFoundError:
    data = ""          # no file yet: start empty

The with statement

Idea: with open(...) as f: closes the file automatically, even if an error happens inside the block. Always prefer it.

with open("expenses.txt", "a") as f:
    f.write("Tea,20\n")
# the file is closed here automatically

5. Which Error Means What?

ErrorWhen it happensSensible response
FileNotFoundErrorReading a file that does not existStart with empty data, or tell the user the file is missing
PermissionErrorThe file is locked or read-onlyTell the user to close the file or check permissions
ValueErrorA line cannot be converted, for example float("abc")Skip that line and count it as bad
IndexErrorA line does not have the expected partsSkip the line and report it

6. The Core Code (Read It Slowly)

FILE = "expenses.txt"

def add_expense(item, amount):
    # "a" = append: old lines stay, new line goes at the end
    with open(FILE, "a") as f:
        f.write(f"{item},{amount}\n")

def total_spent():
    total = 0
    bad_lines = 0
    try:
        with open(FILE, "r") as f:
            for line in f:
                try:
                    item, amount = line.strip().split(",")
                    total += float(amount)
                except ValueError:
                    bad_lines += 1           # damaged line: skip it
    except FileNotFoundError:
        print("No expense file yet. Total is 0.")
    except PermissionError:
        print("Cannot open the file. Close it and try again.")
    if bad_lines:
        print(f"Skipped {bad_lines} damaged line(s).")
    return total

def clear_all():
    # "w" = write: this ERASES everything in the file
    with open(FILE, "w") as f:
        pass

Notice the nesting: the inner try protects one line, and the outer try protects the whole file.

7. Your Task

  1. Write add_expense(item, amount) that appends one line to expenses.txt using "a" mode and the with statement.
  2. Write show_all() that reads and prints every expense line.
  3. Write total_spent() that adds up all amounts. Handle a missing file with FileNotFoundError.
  4. Make a damaged line (for example Lunch,abc) get skipped with ValueError, while the rest still count.
  5. Write clear_all() that uses "w" mode to empty the file, and explain in a comment why this is dangerous.
  6. Test the program on: no file yet, a file with a bad line, and a normal file. Add at least three expenses before the final test.

8. Acceptance Criteria (Tick As You Go)

A damaged line is skipped, the total still includes the good lines, and the number of skipped lines is reported.
PermissionError is caught with a clear message.
clear_all() uses "w" mode, and a comment explains that it erases the data.
The totals are correct after at least three expenses are added.
You can explain in your own words why "a" and "w" give different results.

9. Self-Check Questions

1. What is the difference between mode "w" and mode "a"?

2. Why is with open(...) safer than f = open(...)?

3. Why do we put the try inside the loop for each line, instead of only around the whole file?

4. What does except FileNotFoundError let the program do that a crash would not?
