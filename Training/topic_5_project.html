Mini Online Store

A visual guide to Metaclasses, Decorators in Classes and Abstract Base Classes

1. The Problem

An online store sells different kinds of products: books, electronics, and more. The store software must:

  • Automatically know every product type that has been defined, and refuse any type that is incomplete. Metaclass
  • Block a purchase when stock is empty and log every purchase, without repeating that code in each product. Decorators in classes
  • Force every product type to define its own shipping cost, and stop anyone creating a generic "Product" by mistake. Abstract base class

These are the tools that big frameworks use behind the scenes. You will meet them when reading library code.

2. The Three Ideas

Metaclasses

Idea: A class is an object too. A metaclass is the class that builds classes. It runs when a class is defined.

Real life: a factory inspector who checks every new product design before it is allowed on the shelf.

class ProductMeta(ABCMeta):
    registry = {}
    def __new__(mcs, name, bases, namespace):
        cls = super().__new__(mcs, name, bases, namespace)
        if bases:
            mcs.registry[name] = cls
        return cls

Decorators in Classes

Idea: A decorator wraps a method with extra behaviour. Here, the wrapper runs checks before the method and can log after it.

Real life: a security guard at the door of a shop, checking every customer before they enter.

def require_stock(func):
    def wrapper(self, *args, **kwargs):
        if self.stock <= 0:
            raise ValueError("Out of stock")
        return func(self, *args, **kwargs)
    return wrapper

class Product:
    @require_stock
    def purchase(self):
        ...

Abstract Base Classes

Idea: A class that cannot be used directly. It lists methods that every child must write.

Real life: a job description that says "must be able to drive" — every applicant has to show it.

from abc import ABC, abstractmethod

class Product(ABC):
    @abstractmethod
    def shipping_cost(self):
        ...

Product()   # TypeError: cannot instantiate

6. The Core Code (Read It Slowly)

from abc import ABC, abstractmethod, ABCMeta

# ---------- 1. METACLASS: runs when a product class is DEFINED ----------
class ProductMeta(ABCMeta):
    registry = {}

    def __new__(mcs, name, bases, namespace):
        cls = super().__new__(mcs, name, bases, namespace)
        if bases:                                  # skip the base class itself
            if "category" not in namespace:
                raise TypeError(f"{name} must define category")
            mcs.registry[name] = cls               # register automatically
        return cls

# ---------- 2. DECORATOR: wraps a method ----------
def require_stock(func):
    def wrapper(self, *args, **kwargs):
        if self.stock <= 0:
            raise ValueError(f"{self.name} is out of stock")
        print(f"[log] purchasing {self.name}")
        return func(self, *args, **kwargs)
    return wrapper

# ---------- 3. ABSTRACT BASE CLASS: a rule every child must follow ----------
class Product(metaclass=ProductMeta):
    def __init__(self, name, price, stock):
        self.name = name
        self.price = price
        self.stock = stock

    @abstractmethod
    def shipping_cost(self):
        ...

    @require_stock
    def purchase(self):
        self.stock -= 1
        return self.price + self.shipping_cost()

class Book(Product):
    category = "book"
    def shipping_cost(self):
        return 40

class Electronics(Product):
    category = "electronics"
    def shipping_cost(self):
        return 150

book = Book("Dune", 500, stock=2)
book.purchase()                 # [log] purchasing Dune  -> 540
Product("x", 1, 1)              # TypeError: abstract method

Three tools, three jobs: the metaclass checks the class when it is defined, the decorator wraps the method when it is called, and the ABC rule is checked when an object is created.

7. Your Task

  1. Write a metaclass ProductMeta that registers every product class by name and refuses a class without a category.
  2. Write a decorator require_stock that blocks purchase() when stock is 0 and prints a log line for each purchase.
  3. Write an abstract Product class with an abstract shipping_cost() method.
  4. Create Book and Electronics children, each with its own shipping cost and category.
  5. Show that Product(...) cannot be created, and that a child without shipping_cost() cannot be created either.
  6. Print the registry, then buy items until the stock runs out and show the error.

8. Acceptance Criteria (Tick As You Go)

Every valid product class appears in the registry automatically, with no manual list.
purchase() is blocked when stock is 0, and the decorator is the only place that checks stock.
Each purchase prints a log line, and the purchase() method itself has no print statement.
Product() raises a TypeError, so the abstract class cannot be created.
A child class that does not define shipping_cost() cannot be created.
The program runs without errors for at least two different product lists.
You can explain in your own words when each of the three tools runs: definition time, call time, or object creation time.

9. Self-Check Questions

1. Is a metaclass used when you create an object, or when you define a class? Explain in one sentence.

2. What does a decorator receive as its input, and what does it return?

3. Why is Product an abstract base class instead of a normal class?

4. Why would a store want to put stock checks inside a decorator rather than inside every product's purchase()?
