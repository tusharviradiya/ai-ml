## Make the practical work fit

Use **one small classification dataset and one document collection** throughout. Training, serving, quality gates, monitoring, and security exercises extend Capstone A. Chunking, retrieval, evaluation, tools, safeguards, and tracing extend Capstone B. Keep the developer intake slice as a small component of the document workflow instead of a third large application.

Every lab gets a focused first implementation and a short independent variation or failure investigation. Use hosted labs when available. If a cloud step is inaccessible, record the exact substitute—local implementation, configuration walkthrough, or conceptual exercise. A walkthrough does not establish equivalent deployment experience; mark that limitation in the review.

Do not spend days resolving unavailable subscriptions or building elaborate interfaces. Preserve required learning outcomes, use a suitable accessible alternative, and record what remains unpracticed.

## Daily learning cycle

For a typical 150-minute block, use about 35 minutes for instruction, 75 for a practical task, 30 for questions/corrections, and 10 for evidence/progress updates. The mix changes on assessment days. Review recent mistakes briefly each day.

The calendar never overrides an unresolved prerequisite. If work spills over, use the catch-up allowance and remove duplicate training first. Keep optional course expansion separate. Report slippage and remaining scope rather than compressing the review into a false completion mark.
